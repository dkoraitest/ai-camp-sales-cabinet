# Telegram: канал до менеджера

Кабинет открывает руководитель. Менеджер его не открывает — он живёт в
мессенджере. Поэтому разбор разговора и задание на отработку уходят туда, где
человек их прочитает, через пару минут после звонка, а не на планёрке в пятницу.

## На воркшопе

Бота заводить не нужно — используется общий бот, токен даёт спикер.

1. Скопируйте `.env.example` в `.env` и вставьте туда токен:

   ```bash
   cp .env.example .env
   python3 scripts/telegram.py init
   ```

   `init` спрашивает у Telegram имя бота и кладёт его рядом с кабинетом. После
   этого в карточке каждого менеджера появляется ссылка подключения.

2. Откройте вкладку «Менеджеры», нажмите «Разбор и сообщения» — сверху блок
   «Канал до менеджера» со ссылкой вида `t.me/ваш_бот?start=m2`.

3. Отправьте ссылку менеджеру. Он открывает её и жмёт «Старт» — всё. Вводить
   ничего не нужно: Telegram сам передаёт боту, кто это и к какому менеджеру
   привязывать. На воркшопе откройте свою же ссылку сами, чтобы увидеть разбор
   с той стороны, с которой его видит сотрудник.

4. Заберите привязки и отправьте:

   ```bash
   python3 scripts/telegram.py link --auto     # привязать всех, кто прошёл по ссылке
   python3 scripts/telegram.py send m2 --dry   # сначала посмотреть текст
   python3 scripts/telegram.py send m2         # отправить
   ```

Если у менеджера нет ссылки под рукой, можно привязать по хендлу:
`python3 scripts/telegram.py who` покажет всех, кто писал боту, а
`python3 scripts/telegram.py link m2 --user @denis` свяжет вручную.

Общий бот живёт до конца конференции, после него токен отзывается. Всё, что вы
собрали, останется работать — поменяется только одна строка в `.env`.

Бот общий, поэтому `who` покажет и тех, кто сидит рядом. Секретов там нет, но
имейте в виду. Привязка по ссылке этого не касается: она работает по id
менеджера, а не по списку чатов.

## Свой бот после конференции

Пять минут, один раз.

1. В Telegram напишите **@BotFather** команду `/newbot`
2. Придумайте имя (видно людям) и username (должен заканчиваться на `bot`)
3. BotFather пришлёт токен вида `1234567890:AA...` — это пароль от бота
4. Вставьте его в `.env` вместо токена спикера
5. Попросите каждого менеджера открыть бота и нажать «Старт»
6. Запустите `python3 scripts/telegram.py init` — кабинет узнает нового бота
   и перевыпустит ссылки подключения в карточках
7. Разошлите каждому его ссылку из карточки и соберите привязки:

   ```bash
   python3 scripts/telegram.py link --auto
   ```

Привязки лежат в `active/telegram.json`, а кабинет видит только имя бота и список
подключённых — `cabinet/telegram.js`. Ни токена, ни id чатов там нет, и в
репозиторий не попадает ни то, ни другое.

**Токен в репозиторий не коммитьте.** `.env` закрыт в `.gitignore` — не убирайте
эту строку. Утёкший токен означает, что писать вашим людям от имени компании
сможет кто угодно. Если токен всё-таки где-то засветился, напишите BotFather
`/revoke` и получите новый.

## Что уходит человеку

Два сообщения, оба короткие:

- **После значимого разговора** — что сделано хорошо, с цитатой из его же
  разговора; что упущено; что сделать конкретно в следующий раз
- **Тренировка** — ситуация из реальных возражений вашей базы и просьба
  ответить кружком на минуту

Тексты пишет шаг 2 и складывает в `cabinet/coach.js`. Посмотреть их, ничего не
отправляя: `python3 scripts/telegram.py send all --dry`.

## Дальше: доставка сама собой

Сейчас отправка запускается руками. Следующий шаг — по расписанию: разбор
считается ночью и уходит утром, тренировка — в понедельник. Это `cron` на любой
машине, которая ночью включена:

```
0 8 * * 1-5  cd /путь/к/репозиторию && python3 scripts/telegram.py send all
```

Отвечать на кружки и разбирать ответы бот пока не умеет — это четвёртый режим
тренера, про который говорили на воркшопе.
