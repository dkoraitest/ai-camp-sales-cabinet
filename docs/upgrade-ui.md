# Переделать кабинет в настоящее приложение

Кабинет намеренно собран без единой зависимости: один HTML-файл, который открывается двойным кликом и уходит руководителю вложением. Это его главное свойство, а не техническая бедность — на воркшопе за два часа ничего другого и не соберёшь, а через год он откроется так же, как сегодня.

Но когда кабинетом начинают пользоваться каждый день несколько человек, ванильная вёрстка упирается в потолок: нужны нормальные таблицы с сортировкой, фильтры, графики, тёмная и светлая темы из коробки, мобильная версия. Тогда имеет смысл переписать интерфейс на компонентной библиотеке.

## Что подключено

В репозитории лежит конфиг MCP-сервера [shadcn/ui](https://ui.shadcn.com/docs/mcp) — для Claude Code это `.mcp.json`, для Cursor `.cursor/mcp.json`. Сервер даёт агенту доступ к каталогу готовых компонентов: он умеет их искать, показывать и ставить в проект по обычной просьбе вроде «добавь таблицу с сортировкой и фильтром по менеджеру».

Чтобы MCP заработал, перезапустите агента в этой папке. Проверить: спросите «какие компоненты есть в shadcn для таблиц».

## Когда этим пользоваться

**Не на первом запуске.** shadcn — это React и Tailwind: нужен `npm install`, сборка и dev-сервер. Кабинет перестанет открываться двойным кликом и превратится в проект, который нужно запускать. На конференции это съест время, которое должно уйти на ваши данные.

**После конференции, когда выполнены два условия:** кабинет работает на ваших реальных разговорах, и им пользуется больше одного человека. До этого момента переделывать интерфейс рано — вы будете полировать витрину вместо того, чтобы разбираться с содержимым.

## Как переходить

Порядок имеет значение: сначала данные, потом интерфейс.

1. **Сохраните то, что работает.** `blocks/` и `scripts/` трогать не нужно — вся логика разбора, генерации и агрегатов остаётся как есть. Меняется только слой отображения
2. **Поднимите проект:** `npx shadcn@latest init`, дальше агент поставит нужные компоненты через MCP
3. **Перенесите вкладки по одной**, начиная с Коммуникаций — там больше всего выигрыша от нормальной таблицы. Обзор переносите последним: он и в ванильном виде читается хорошо
4. **Оставьте экспорт в один файл.** Возможность отдать кабинет коллеге вложением — то, за что его любят. Если она исчезнет, вы получите ещё одну систему, в которую надо логиниться

## Что попросить у агента

Формулировки, которые работают лучше общих просьб:

- «Перенеси вкладку Коммуникации на shadcn: таблица с сортировкой по баллу, фильтрами по этапу и менеджеру, раскрытием строки в диалог с транскриптом»
- «Сделай карточку менеджера: радар по семи навыкам, обратная связь, кейс на отработку»
- «Собери страницу Обзор: KPI-плитки, воронка горизонтальными полосами, гистограмма распределения оценок»

Данные берите из тех же файлов: `data.js`, `scores.js`, `coach.js`, `enrich.js`, `deep.js`. Формат описан в [architecture.md](architecture.md).

## Чего делать не стоит

- Переписывать `scripts/` — это рабочая логика, она не про интерфейс
- Тащить бэкенд, пока данные помещаются в файл. Для отдела продаж это верно до нескольких тысяч разговоров
- Делать авторизацию раньше, чем появится второй пользователь
