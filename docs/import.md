# Импорт своих разговоров

Лучший вариант из возможных: кабинет на настоящих разговорах вашего отдела. Синтетика показывает механику, реальные данные показывают ваш бизнес.

**Сколько нужно.** Двадцати разговоров достаточно, чтобы увидеть первые закономерности. Ста — чтобы им доверять. Трёхсот — чтобы считать сегментные разрезы и глубокую аналитику.

## Что подойдёт

| Откуда | Как выгрузить | Формат |
|---|---|---|
| WhatsApp | в чате «⋯ → Ещё → Экспорт чата → Без медиафайлов» | `.txt` |
| Telegram | Telegram Desktop: «⋯ → Экспорт истории чата → JSON» | `result.json` |
| Звонки | расшифровка из телефонии или сервиса речевой аналитики, с метками говорящих | `.txt`, `.md`, `.docx` |
| Встречи | субтитры Zoom, Meet, Teams | `.vtt`, `.srt` |
| CRM или аналитика | таблица с колонками «разговор, дата, говорящий, текст» | `.csv` |

Расшифровка подойдёт в любом из видов: `Менеджер: …`, `Спикер 1: …`, `[00:01:23] Айгуль: …`, `Айгуль (00:01:23): …`. Строка без метки считается продолжением предыдущей реплики.

PDF, аудио и скриншоты скрипт не читает. Их агент приведёт к расшифровке вручную, а аудио нужно сначала расшифровать в сервисе транскрибации.

## Как импортировать

Сложите файлы в `data/import/` и скажите агенту:

```
импортируй мои разговоры
```

Дальше он сделает так:

1. **Разбор** — `python3 scripts/import_data.py scan`: код читает форматы и раскладывает файлы на разговоры и реплики
2. **Сопоставление** — агент проверяет догадки в `data/import/_mapping.json` и спрашивает только то, чего в файлах нет: кто менеджер под меткой «Спикер 1», какие разговоры — один и тот же клиент, чем закончились закрытые сделки
3. **Сборка** — `python3 scripts/import_data.py build`: база кабинета в `data/own/dataset.json`

Профиль и воронка нужны заранее: их собирают окна шага 0. Если профиля ещё нет, агент начнёт с них.

## Сопоставление

`data/import/_mapping.json` — единственное место, где решается смысл. Его можно править и руками:

```json
{
  "managers": { "Айгуль Жумабаева": "m1", "Спикер 1": "m1", "Оператор": "m2" },
  "manager_names": { "m1": "Айгуль Жумабаева", "m2": "Марина Ли" },
  "conversations": {
    "imp001": { "lead": "Мега Склад", "stage": null, "outcome": "", "value_kzt": null, "result": null },
    "imp002": { "lead": "Мега Склад", "stage": "demo", "outcome": "договорились о пробной партии",
                "value_kzt": 1200000, "result": null },
    "imp003": { "lead": "Балапан Той", "stage": null, "outcome": "купили у конкурента", "result": "lost" }
  }
}
```

- `managers` — говорящий → id менеджера; все остальные считаются клиентами
- `lead` — одинаковое имя склеивает разговоры в одну сделку
- `stage` — id этапа вашей воронки; `null` — этап по порядку разговоров
- `result` — `won` или `lost` для закрытых сделок

После правки — снова `python3 scripts/import_data.py build`. Повторный `scan` заполненное сопоставление сохраняет.

## Мало разговоров

Импортируйте то, что есть, и догенерируйте до рабочего объёма:

```bash
python3 scripts/import_data.py build --top-up 200
```

Синтетика достанется вашим же менеджерам и помечается: в таблице коммуникаций у таких разговоров пометка «синтетика», в шапке кабинета — «ваши записи + синтетика». Генератор напрямую запускать не нужно — он откажется перезаписывать импорт.

## Формат базы

Если хотите собирать базу своим скриптом, например из выгрузки CRM, — полная схема в [architecture.md](architecture.md), контракт для CRM в [connectors/](../connectors/).

## О чём предупредить команду

Разговоры сотрудников — чувствительные данные. Прежде чем загружать записи, убедитесь, что у вас есть на это право: предупреждение о записи в начале звонка, согласие сотрудников, политика хранения.

Папка `data/import/` закрыта в `.gitignore` — записи в репозиторий не попадают. Кабинет работает локально; наружу уходят только вызовы модели, которые делает агент, пока работает с файлами.
