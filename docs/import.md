# Импорт своих разговоров

Лучший вариант из возможных: кабинет на настоящих разговорах вашего отдела. Синтетика показывает механику, реальные данные показывают ваш бизнес.

**Сколько нужно.** Двадцати разговоров достаточно, чтобы увидеть первые закономерности. Ста — чтобы им доверять. Трёхсот — чтобы считать сегментные разрезы и глубокую аналитику.

## Что подойдёт

| Откуда | Как выгрузить | Формат |
|---|---|---|
| WhatsApp, Android | в чате «⋯ → Ещё → Экспорт чата → Без медиафайлов» | `.txt` |
| WhatsApp, айфон | имя контакта → «Экспорт чата» → «Без медиафайлов» | `.zip` — кладите как есть |
| Telegram | Telegram Desktop: «⋯ → Экспорт истории чата → JSON» | папка `ChatExport_…` целиком или `result.json` |
| Звонки | расшифровка из телефонии или сервиса речевой аналитики, с метками говорящих | `.txt`, `.md`, `.docx` |
| Встречи | субтитры Zoom, Meet, Teams | `.vtt`, `.srt` |
| CRM или аналитика | таблица с колонками «разговор, дата, говорящий, текст» | `.csv` |

Расшифровка подойдёт в любом из видов: `Менеджер: …`, `Спикер 1: …`, `**Айгуль:** …`, `[00:01:23] Айгуль: …`, `Айгуль (00:01:23): …`, а также как у Teams и Word — строка «Айгуль Жумабаева   0:03», под ней реплика. Строка без метки — продолжение предыдущей реплики. Кодировка любая из обычных: UTF-8, UTF-16, cp1251.

Заметки без реплик, расшифровки без меток говорящих, pdf, аудио и скриншоты скрипт не читает и называет причину. Дальше агент поступает так:
- **заметки и итоги встреч** переносит в `data/import/_done/`, туда скрипт не смотрит. Это пересказ, в диалог его не превращают: придуманные реплики попали бы в оценки менеджеров
- **расшифровку без меток** размечает «Имя: реплика», только если по тексту ясно, кто говорит, и сохраняет рядом как `.txt` с датой и компанией в имени файла. Оригинал тоже уходит в `data/import/_done/`
- **аудио и голосовые** нужно сначала расшифровать в сервисе транскрибации

Полный архив Telegram можно класть целиком. Чаты без признаков работы - «Мама», «Избранное» - скрипт отложит сам. Рабочий чат без слов про деньги («Удобно созвониться завтра?») он вернёт, если в нём пишет клиент известной сделки или сделка звучит в названии чата. Два чата с одинаковым названием различаются по id из экспорта.

## Как импортировать

Сложите файлы в `data/import/` и скажите агенту:

```
импортируй мои разговоры
```

Дальше он сделает так:

1. **Разбор** — `python3 scripts/import_data.py scan`: код читает форматы и раскладывает файлы на разговоры и реплики
2. **Сопоставление** — агент проверяет догадки в `data/import/_mapping.json` и спрашивает только то, чего в файлах нет: кто менеджер под меткой «Спикер 1», какие разговоры — один и тот же клиент, чем закончились закрытые сделки
3. **Сборка** — `python3 scripts/import_data.py build`: база кабинета в `data/own/dataset.json`

Профиль и воронка нужны заранее: их собирают окна шага 0. Если профиля ещё нет, агент начнёт с них.

## Сопоставление

`data/import/_mapping.json` — единственное место, где решается смысл. Ключ разговора — имя файла (и название чата внутри файла), поэтому новые файлы не сдвигают то, что уже заполнено. Его можно править и руками:

```json
{
  "_этапы": { "first_contact": "Первый контакт", "samples": "Образцы", "first_shipment": "Первая отгрузка", "lost": "Проиграна" },
  "managers": { "m1": "Айгуль Жумабаева", "m2": "Асель Ким" },
  "conversations": {
    "2026-09-15_звонок_Мега_Склад.txt": {
      "title": "2026-09-15_звонок_Мега_Склад", "date": "2026-09-15T00:00", "kind": "call",
      "preview": "Спикер 1: Алло. / Спикер 2: Ерлан, добрый день! Это Айгуль, компания Qazaq Pack…",
      "speakers": { "Спикер 2": "m1", "Спикер 1": "client" },
      "lead": "Мега Склад", "stage": null, "outcome": "выслать КП", "exclude": false
    },
    "result.json#Мама": { "…": "…", "exclude": true }
  },
  "leads": { "Мега Склад": { "result": "won", "value_kzt": 2400000 } }
}
```

- `managers` — id → имя. Один человек — один id: если Айгуль в одном файле «Айгуль Жумабаева», в другом «Спикер 2», а в третьем «Aigul», во всех трёх разговорах стоит `m1`
- `speakers` — роли в **этом** разговоре: id менеджера или `client`. «Спикер 1» во входящем звонке может быть менеджером, а в исходящем — клиентом. `m?` — менеджер, но не ясно какой
- `lead` — одинаковое имя склеивает разговоры в одну сделку
- `stage` — id этапа из `_этапы`; `null` — этап по порядку разговоров в сделке
- `date` — поправьте, если в файле не было даты
- `exclude: true` — разговор не про продажи
- `leads` — итог сделки: `result` (`won`, `lost` или `null`) и `value_kzt`

Как скрипт угадывает:
- **менеджер** - тот, кто говорит с разными клиентами, называет вашу компанию или представляется по имени. «Aigul» и «Айгуль» - один человек. Метка без фамилии («Марат») достаётся менеджеру Марату Садыкову, только если другого Марата в записях нет, и такие разговоры скрипт просит проверить
- **сделка** - из имени файла или чата. «Ерлан Мега Склад» склеивается с «Мега Склад», если Ерлан в этом чате клиент. «Каспий» склеивается с «Каспий Трейд», если в обоих звучит один и тот же клиент. Безымянный звонок относится к сделке, которую клиент называет вслух. Остальные похожие названия скрипт не склеивает и выводит списком: «Мега Склад» и «Мега Склад Астана» бывают одной компанией, бывают разными

Всё это догадки. Сверьте каждую сделку по `preview`: в `lead_why` написано, откуда она взялась.

После правки - `python3 scripts/import_data.py build`. Если что-то не заполнено - `m?`, разговор без менеджера, неизвестный id, этап не из воронки, - скрипт базу не соберёт и перечислит, что поправить. Повторный `scan` заполненное сохраняет.

Что ещё стоит знать про правку:
- **Переименовали сделку в `lead` - перенесите её запись в `leads`.** Итог и сумма привязаны к имени сделки. Записи, которые остались без сделки, `build` перечислит
- **Длинной переписке ставьте этап явно.** «По порядку» она получит один этап, хотя за месяц переписки сделка проходит несколько

**После импорта шаги 1-4 проходятся заново.** Разборы прежней базы скрипт отложит в `active/before-import/`: их id совпадают с новыми, а люди и сделки - другие. Ещё две вещи `build` делает сам:
- если до этого включали демо, возвращает конфиг вашей компании из `active/before-demo/` или собирает его из профиля
- сбрасывает привязки Telegram: после импорта за `m1`, `m2` стоят другие люди, и разбор мог бы уйти не тому. Разошлите менеджерам ссылки из их карточек заново, агент перепривяжет

## Мало разговоров

Импортируйте то, что есть, и догенерируйте до рабочего объёма:

```bash
python3 scripts/import_data.py build --top-up 200
```

Это «до 200 разговоров всего», считая ваши. Синтетика идёт от отдельных синтетических менеджеров и сделок: оценки ваших людей, их среднее и место в команде считаются только по их разговорам, а в кабинете у синтетики пометка. Имена людей в синтетике нейтральные, ни имён, ни фамилий из ваших записей и профиля. Если синтетики больше половины, плашка в шапке так и пишет. Генератор напрямую запускать не нужно - он откажется перезаписывать импорт.

## Формат базы

Если хотите собирать базу своим скриптом, например из выгрузки CRM, — полная схема в [architecture.md](architecture.md), контракт для CRM в [connectors/](../connectors/).

## О чём предупредить команду

Разговоры сотрудников — чувствительные данные. Прежде чем загружать записи, убедитесь, что у вас есть на это право: предупреждение о записи в начале звонка, согласие сотрудников, политика хранения.

Папка `data/import/` закрыта в `.gitignore` — записи в репозиторий не попадают. Кабинет работает локально; наружу уходят только вызовы модели, которые делает агент, пока работает с файлами.

## Если правите скрипт импорта

`python3 tests/test_import.py` - самопроверка на синтетических файлах всех форматов и неудобных случаев: роли «Спикер 1» в разных звонках, латиница, метки без фамилии, личные и рабочие чаты, похожие названия компаний, заметки, кодировки, повторный разбор, догенерация. Запускайте после любой правки `scripts/import_data.py`.
