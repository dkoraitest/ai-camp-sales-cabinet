# Шаг 1 · Аналитика коммуникаций

Кабинет знает матрицу. Теперь он должен прочитать разговоры **и переписку** и сказать, что там происходит.

**Главная мысль шага:** качество разговора — не мнение руководителя, а измеримая величина. Как только оно измеримо, им можно управлять.

## Что делаешь

1. Читаешь `cabinet/config.js` — матрица, воронка, фокусный этап
2. **Размечаешь всю базу кодом:**

```bash
python3 scripts/score_all.py
```

Скрипт проходит по всем контактам — их сотни — и считает семь показателей матрицы по формальным признакам: сколько вопросов задано до первого упоминания продукта, дошёл ли разговор до цифры потерь, зафиксирован ли следующий шаг, выяснены ли бюджет и ЛПР, какая доля речи у менеджера. Результат: `active/scored.json` (оценки всех контактов) и `active/aggregates.json` (готовые разрезы).

Гонять сотни разговоров через модель поштучно нельзя: это десятки тысяч токенов, минуты ожидания и обрыв на середине у части зала. Код делает объём, ты приходишь туда, где нужен смысл.

3. **Читаешь `active/aggregates.json`** — там четыре разреза, каждый на своём месте (см. ниже)
4. **Разбираешь по смыслу два-три десятка показательных контактов**: лучший, худший, переломный, пару из переписки. Им пишешь человеческие комментарии и заполняешь `extracted` — это то, чего код не умеет
5. Пишешь инсайты в `cabinet/scores.js` поверх готовых оценок из `active/scored.json`
6. **Собираешь кабинет** — на этом шаге он появляется впервые:

```bash
python3 scripts/build_cabinet.py --blocks me,overview,contacts,insights
python3 scripts/build_data.py
```

## Четыре разреза, каждый на своём месте

**1. Качество коммуникаций — на фокусном этапе.** Сравнивать между собой можно только сопоставимое: в одной таблице не должны оказаться «не дозвонились» и «думает над КП». В `aggregates.focus` — средний балл этапа, сколько разговоров начинается с продукта, сколько доходит до цифры потерь, разбивка по менеджерам.

**2. Инсайты — по всей воронке.** Иначе не видно, где теряются деньги, а не контакты. В `aggregates.funnel` — по каждому этапу: сколько контактов, средний балл, сколько сделок стоит и на какую сумму. В `aggregates.behaviour_vs_outcome` — связь поведения с исходом: доходят ли дальше сделки, где зафиксировали следующий шаг, где довели до цифры, где ответили на возражение вопросом, а не скидкой.

**3. BANT — на этапе квалификации.** Там, где он должен происходить, а не «в среднем по больнице». В `aggregates.bant` — покрытие по каждому из четырёх признаков, сколько контактов прошли полную квалификацию и как это связано с исходом.

**4. SPSV — по всей воронке.** Части модели клиента всплывают на разных этапах: ситуация на первой встрече, ценность ближе к КП. В `aggregates.segments` — по каждому сегменту количество сделок, win rate, среднее качество разговоров и частые реплики клиентов. Из них собирается сегмент — ситуация — проблема — решение — ценность.

**Про объём говори честно.** Оценки по всей базе считает код: он видит признаки, но не понимает иронии и формальных вопросов «для галочки». Смысловой разбор — по выборке. Скажи это одной фразой, без оправданий.

## Звонки и переписка — равноправные контакты

Переписку разбирай по тем же показателям. Там свои провалы, которых не видно в звонках:

- серия напоминаний без единого нового аргумента («отправил», «напоминаю», «есть новости?»)
- торг о скидке, ушедший в мессенджер, где ценность уже не звучит
- прайс, отправленный без контекста и без вопроса
- и наоборот — снятое через переписку скрытое возражение, о котором в звонке не говорили

Склейка простая: у контакта есть `lead_id` и `stage`, этого достаточно, чтобы положить его в нужное место воронки.

## Как оценивать

Каждый показатель — 0–10. Ориентиры: 0–3 не делал или формально, 4–6 поверхностно, 7–8 хорошо, 9–10 образцово, можно показывать команде как эталон. Итоговый балл — среднее по показателям.

**Комментарий к контакту** — одно предложение: что именно определило оценку. Так, чтобы менеджер понял, а не обиделся: «перешёл к презентации до того, как выяснил, что болит» лучше, чем «плохо провёл discovery».

## Что извлекаешь (слой 1)

Для ключевых контактов заполни `extracted`: SPSV словами клиента, квалификацию (что подтверждено, а что додумано), возражения дословно, следующий шаг, сигналы. Это не украшение — из SPSV потом собирается сегментная аналитика на шаге 4.

## Как искать закономерности

Не ограничивайся средними:

- **Разброс внутри команды** — кто выше и ниже среднего и по каким показателям
- **Связь поведения с исходом** — что делали иначе в контактах, после которых сделка двинулась
- **Звонки против переписки** — где команда проседает сильнее
- **Повторяющиеся возражения** — дословно, с частотой
- **Самый слабый показатель по базе** — точка, где обучение даст максимум
- **Для b2c** — связь скорости реакции (`responded_in_min`) с исходом
- **Для b2b** — связь зафиксированного следующего шага со стадией сделки

Сравнивай контакты одного этапа. Если сравниваешь разные — скажи об этом прямо.

## Формат файла

```js
window.CABINET_SCORES = {
  items: [
    { id:"c01", type:"call", total:2.9, stage:"discovery", lead_id:"l07",
      evaluate:[{id:"structure", name:"…", value:6, max:10}, …],
      bant:{ budget:false, authority:true, need:true, timing:false },
      extracted:{ spsv:{…}, qualification:{…}, objections:[…], next_step:"…", signals:"…" },
      comment:"…" },
    { id:"ch01", type:"chat", total:2.0, evaluate:[…], comment:"…" }
  ],
  aggregates: { … },                                    // целиком из active/scored.json
  insights: [ { level:"bad|warn|good", title:"…", text:"…" } ]
};
```

**Разрезы для графиков скрипт уже положил в `cabinet/aggregates.js` сам** — их переносить не нужно, кабинет читает их оттуда. В `scores.js` пиши `items` из `active/scored.json` как есть и свои `insights`. Это считает код, и кабинет на этом рисует графики: `bant` и `lead_id` у каждого контакта нужны для графика квалификации на вкладке «Обзор» (сколько было звонков-квалификаций в день и в скольких прозвучал каждый признак) и для разбивки по воронке на вкладке «Глубокая аналитика», `aggregates.won_vs_lost` — для сравнительной таблицы там же. Твоя работа — `insights` и семантический разбор двух-трёх десятков контактов, а не перенабор цифр.

Инсайтов 5–8, каждый с цифрой и выводом. В эталоне есть ещё три с `scope:"base"` — это пример шага 4, на шаге 1 их не пиши. Инсайт без числа — это мнение, а не аналитика. Эталон — `reference/scores.js`.

## Что сказать участнику

Один разбор, два взгляда. Первым открываем менеджера:

«Кабинет открылся в браузере — если нет, откройте `cabinet/index.html` двойным кликом. Сверху переключатель — сейчас ты Менеджер. Выбери себя в списке "Я" и открой **Мои звонки**: твой балл по семи показателям рядом со средним по команде. Смотри не на самую короткую полосу, а на самый большой разрыв». Дай 30 секунд посмотреть.

Потом **Мои сделки** (B2B) или **Моя очередь** (B2C): портфель по этапам, застрявшие, просроченный следующий шаг; у B2C — заявки по приоритету. Клик по строке открывает карточку: все разговоры по ней одной лентой и места под модули «до контакта» и «после контакта» — их заполнит шаг 3.

Переключение на Руководителя — позже, в блоке руководителя: там дашборд, коммуникации, инсайты. Если участник спросит сам — покажи, это тот же разбор, только по всему отделу.

## Аварийный выход

Если на шаге что-то сломалось или не хватает времени — `включи демо` (`python3 scripts/demo_step.py`): в кабинет ляжет эталон этого шага, и участник пройдёт дальше.
