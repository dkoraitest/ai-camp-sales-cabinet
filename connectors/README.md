# Коннекторы к CRM

Кабинет — рабочий слой поверх CRM. CRM остаётся системой учёта, кабинет читает из неё сделки и возвращает то, что раньше вносил менеджер.

Сегодня данные лежат в `data/` файлами. Коннектор — это скрипт, который делает такой же файл из вашей CRM:

```
API CRM  →  scripts/connectors/<crm>.py  →  data/own/dataset.json  →  build_data.py  →  кабинет
```

Браузер в CRM не ходит: правило «никакого fetch» соблюдается, ключи API остаются в `.env` и не попадают в страницу.

## Контракт: что кабинету нужно от любой CRM

Формат — `data/<profile>/dataset.json`, подробно в [docs/architecture.md](../docs/architecture.md).

**Сделка или заявка** (`leads[]`):

| Поле кабинета | Что это | Обязательно |
|---|---|---|
| `id` | id сделки в CRM | да |
| `stage` | этап воронки, id из `profile.stages` | да |
| `owner` | id ответственного менеджера | да |
| `value_kzt` | сумма сделки | да |
| `source` | источник лида | да |
| `created` | дата создания | желательно |
| `next_step` | дата следующего шага | желательно |
| `company`, `contact`, `position` | компания и контакт (B2B) | для B2B |
| `events` | внешние события: дата, тип, заголовок, источник | нет |

**Менеджер** (`managers[]`): `id`, `name`, `role`.

**Воронка** (`profile.stages`, `profile.stage_labels`): этапы по порядку, два последних — «выиграна» и «проиграна».

**Разговоры** (`calls[]`, `chats[]`) приходят не из CRM, а из телефонии и мессенджеров. Связь с CRM — поле `lead_id`: к какой сделке относится разговор. Без него звонок и сделка остаются несвязанными.

## Запись обратно

Автозадачи шага 3 показывают превью «уйдёт в CRM»: следующий шаг с датой, этап, ЛПР, BANT, риск, задачи. Коннектор с записью берёт эти поля из `cabinet/enrich.js` и отправляет в CRM методами обновления сделки и создания задачи.
