# Шаг 3 · Следующее касание

Кабинет умеет разбирать разговоры и учить команду. Здесь он помогает менеджеру с тем, что тот делает каждый день: следующим касанием по конкретной сделке. До контакта — зачем звонить и что сказать. После — что записать, кому что обещали и что уйдёт в CRM.

**Главная мысль шага:** исход разговора решается до звонка, а порядок в CRM — сразу после. И то и другое можно не делать руками.

Всё на данных участника и без веб-поиска: внешние события по компании уже лежат в базе. В реальной работе их приносит коннектор к новостям, hh.kz и госзакупкам, архитектура карточки от этого не меняется. Скажи это вслух одной фразой.

## Что делаешь

**1. Предложи сделку, а не спрашивай.** Возьми менеджера, которого участник выбрал в «Я» (по умолчанию — у кого больше всего разговоров), и получи кандидатов:

```bash
python3 scripts/touch_context.py --manager m1
```

Скрипт покажет четыре сделки, где касание нужнее всего: просроченный шаг, тишина, свежие события у клиента. Задай один вопрос окном (`AskUserQuestion` в Claude Code, `request_user_input_async` в Codex) — эти четыре сделки вариантами, первая с пометкой «(рекомендую)» и причиной в описании. **Это окно обязательно:** участник должен узнать свою сделку, иначе касание останется чужим. Если он не выбирает — бери первую.

**2. Прочитай контекст одной сделки:**

```bash
python3 scripts/touch_context.py l032
```

Там карточка CRM, внешние события, все разговоры по порядку и то, что из них извлёк шаг 1. Больше ничего читать не нужно — не открывай `data.js` целиком.

**3. Собери касание** и допиши его в `cabinet/enrich.js`, поле `touch` (формат ниже). Если файла нет — создай. Если в нём уже есть `leads` — не трогай их.

**4. Подключи вкладку «Лиды» для руководителя:**

```bash
python3 scripts/build_cabinet.py --add leads
```

**5. Скажи участнику,** куда смотреть. B2B: «Менеджер → Мои сделки. У сделки пометка "касание готово", открой её: сверху повод и сообщение, в середине все разговоры, внизу автозадачи и что уйдёт в CRM». B2C: «Менеджер → Моя очередь. Заявка с пометкой "ответ готов" стоит первой строкой, открой её».

## Из чего собирается касание

**До контакта**

- **Повод касания** — одно-два предложения: что изменилось у клиента или в сделке и почему звонить надо сейчас. Сильнее всего работает связка «внешнее событие + то, что клиент сам сказал раньше». Тендер на наш продукт при пилоте, который обсуждали месяц назад, — повод. «Давно не общались» — не повод
- **Из прошлых разговоров** — 4–6 фактов с номером разговора: боль в цифрах, кто решает, сроки, о чём договорились, где сделка буксует. Только то, что клиент сказал сам
- **Что произошло у клиента** — внешние события из базы, каждое с выводом для сделки одной фразой
- **Досье ЛПР** (B2B) или **контекст заявки** (B2C): роль в решении, на что реагирует, на что нет — по его же разговорам
- **Сообщение для касания** — 4–6 предложений: зацепка из его реальности, связь с проблемой, что мы с этим делаем одной фразой, конкретный следующий шаг с временем

**КП (B2B) или ответ в мессенджер (B2C)**

- B2B: сначала SPSV из разговоров сделки — сегмент, ситуация, проблема, решение, ценность, — потом короткое КП на его цифрах: что сейчас, что предлагаем, как запускаем, стоимость и за счёт чего окупается
- B2C: ответ в мессенджер на последний вопрос клиента, 3–5 предложений, без прайса первым сообщением

**После контакта — автозадачи**

- **Саммари** — где сделка сейчас, три-четыре предложения
- **Договорённости обеих сторон** — отдельно, что обещали мы и что обещал клиент
- **Задачи** — с датами, у каждой понятный результат
- **Письмо клиенту** — фиксация договорённостей его словами
- **Уйдёт в CRM** — поля, которые слой запишет сам: следующий шаг с датой, этап, ЛПР, BANT, риск, задачи. Это превью: запись в CRM появится, когда подключат коннектор (`подключи CRM`)

**Чего не делает касание:**
- не перечисляет функции продукта
- не предлагает скидку первым ходом
- не содержит «уникальный», «инновационный», «индивидуальный подход»
- не начинается с «Меня зовут… Наша компания является…»

Проверка: если сообщение можно отправить другой компании, заменив название, — оно не готово.

## Формат файла

```js
window.CABINET_ENRICH = {
  leads: [ /* если уже были — оставь */ ],
  touch: [{
    lead_id: "l032",
    before: { reason: "…", memory: ["… (c108)"], events: ["08.09 · goszakup: …"], dossier: "…" },
    message: "…",
    offer: { spsv: { "Сегмент": "…", "Ситуация": "…", "Проблема": "…", "Решение": "…", "Ценность": "…" },
             text: "…" },                        // B2C: только text — ответ в мессенджер
    after: {
      summary: "…",
      agreements: { we: ["…"], client: ["…"] },
      tasks: [{ text: "…", due: "16.09" }],
      email: "…",
      crm: { "Следующий шаг": "…", "Этап": "…", "ЛПР": "…", "BANT": "…", "Риск": "…" }
    }
  }]
};
```

Эталон — `reference/enrich.js`, сделка Каспий Логистикс.

## Если осталось время

Скажи участнику: следующее касание — одна карточка за раз, в реальной работе это делается по каждой сделке перед звонком. Если хочет — подготовь ещё одну, по другой сделке из списка кандидатов.

## Аварийный выход

Если на шаге что-то сломалось или не хватает времени — `включи демо`: в кабинет ляжет эталон этого шага, и участник пройдёт дальше.
